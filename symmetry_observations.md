- There are rotational symmetries that can be handled as one single case. There are 4-rotational symmetries, which means the position remains unchanged up to 90 degrees rotations, so four of these discrete until now cases can be reduced into just one. There are also 2-rotational symmetries, which means the position remains unchanged up to 180 degrees rotations, so two of these discrete until now cases can be reduced into just one. For both of these possible symmetry groups, the best move for one of the cases is also the best move for the other cases if we rotate the board properly, and apply the mapped move on the rotated board.
- There are reflection symmetries that can be also handled in a unified way, reflections along the vertical and the horizontal axis. Here, we can do two compressions. If the rotation action of the board is "still", then two reflected cases can be reduced into a single one, with the best move mapped accordinggly by reflection. If the rotation action of the board is "clockwise" or "counterclockwise", then the wquivalent state of the reflected board should have rotation action "counterclockwise" or "clockwise" respectively, and the best move should maooed accordingly by reflection. So, there is no need for having both the subfolders "clockwise" and "counterclockwise", we can keep only the folder "clockwise", and if "counterclockwise" is asked we map the move from the tablebase accordingly.
- Let the inverse s- of game state s be the one occuring after substituting "1" for "2" and "2" for "1". If player1 plays in state s, this is equivalent to player 2 playing in state s-. So, there is no need for the two subfolders player1 and player2. Assume for the saved solutions that it's player's 1 turn, and if the player's 2 turn is asked, then map the move from the tablebase accordingly.
- The subfolders for "transfer allowed" and "transfer not allowed" should continue to exist, they cannot be compressed. Of course, the transfer move are also mapped accordingly in the cases we discussed above.
